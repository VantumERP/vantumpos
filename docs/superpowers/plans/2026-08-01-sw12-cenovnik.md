# SW-12 — Mašinski čitljiv cenovnik — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Generate a compliant machine-readable cenovnik per prodajni objekat, republish it on every price write, keep an immutable archive of published snapshots, and guard the till against ringing above the published price — with publication modelled as a pluggable target so the hosting decision stays with the founder.

**Architecture:** A pure `cenovnik.rs` renders the file from the catalog; a `PublishTarget` trait abstracts where it goes, with a local-folder implementation and a documented "not configured" state. Publication hangs off the existing `price_history` write path (migration v9) rather than inventing a second source of truth. Snapshots are immutable rows plus a current pointer.

**Tech Stack:** Rust (rusqlite, serde) + Tauri v2 commands; React 19 + TypeScript + shadcn/ui + vitest; bun.

## Global Constraints

- **Money is integer minor units (para).** Never floating point. The CSV renders 2 decimals from integer para at the boundary only.
- **Timestamps RFC3339 passed as a `now: &str` param.** Never `datetime('now')` in decision code.
- **Serbian Latin diacritics** in every operator string; Serbian quotes open `„` and close `“`.
- **Migrations APPEND-ONLY.** Read the current count from `db/mod.rs` first — the ZZPL trio leaves it at 18, so this is **v19**.
- **NO fine figure outside `legal.rs`**, and any new notice goes into **both** guard lists with the count bumped.
- **The literal `200.000` must not be reachable as a preduzetnik's čl. 6 exposure.** Preduzetnik is **fixed 100.000 (čl. 210 st. 3)**, halved to 50.000 on payment within 8 days.
- **Never assert the customer is currently in breach.** The no-website case is unresolved (§2b).
- **Never claim exposure since 1 May 2026** — čl. 210 was not in the čl. 220 carve-out.
- **Never boot the app.** Verify only via the gates.

### Task 1: Migration v19 — snapshots + the unit-price fields

**Files:** Modify `db/migrations.rs`, `db/mod.rs`.

`cenovnik_snapshots`: `id`, `prodajno_mesto`, `generated_at`, `row_count`, `content_hash`, `body` (the rendered file), `published_at`, `published_target`, `created_at`. **Immutable — no `updated_at`.** A `current` pointer is derived as `MAX(generated_at)` per outlet rather than stored, so there is no pointer to get out of sync.

`products` gains `jedinicna_cena_jedinica` (the measure the unit price is expressed in, e.g. `kg`, `l`, `kom`) — nullable, because a product priced per piece may legitimately have none — and `jedinicna_cena_sadrzaj_milli`, the content of one selling unit in that measure. Without the second column the unit price of anything sold by package could only be a copy of the sale price, which is the defect req. 10 names. **`_milli` here is the schema-wide scale, value × 1000, so a 0,75 l bottle is `750`** — Task 2 divides by it, so a renderer assuming any other scale publishes a jedinična cena wrong by three orders of magnitude.

- [ ] **Step 1: Write the failing tests** — the table exists; a snapshot row cannot be updated (assert no `updated_at` column and that the schema guard lists the table); `products.jedinicna_cena_jedinica` exists; **a v18-seeded survival test applying `MIGRATIONS[..18]` to a raw Connection, seeding, `drop(conn)`, then `Db::new`** — mirror commit `270796c`.

### Task 3: Republish on write (req. 11)

**Interfaces:** `publish_current(state, prodajno_mesto, now) -> Result<SnapshotId, AppError>`, hooked into the catalog price-write path.

**A nightly batch is a defect against čl. 6 st. 3, not a simplification.**

**Carried forward from the Task 1 review — v19 does not enforce this, so Task 3 must.** The immutability triggers stop every `UPDATE`, but `INSERT OR REPLACE` is a DELETE plus an INSERT that no trigger sees, so it silently rewrites a published body and drops its `published_at`. The engine cannot close it without closing the čl. 213 purge Task 4 needs. **The publish path uses a plain `INSERT` only — never `INSERT OR REPLACE`, never `ON CONFLICT DO UPDATE`** — and this needs its own assertion, because the idiomatic implementation of the dedupe option below is exactly an upsert. Also: derive `prodajno_mesto` from settings, never accept it from the frontend — it is free text with no FK, so a typo starts a second archive lineage and leaves the Task 5 guard with no published snapshot for the real outlet.

Two writes in the same second are the case the v19 tie-break exists for: current is `ORDER BY generated_at DESC, id DESC LIMIT 1`, so the later insert wins.

- [ ] **Step 1: Write the failing tests** — saving a product price writes a new snapshot; saving a *non-price* field does **not**; two writes in the same second still produce two distinct snapshots (or one, deliberately deduped by `content_hash` — pick one and test it); the previous snapshot remains retrievable afterwards; the publish path never issues a REPLACE or an upsert against `cenovnik_snapshots`.
- [ ] **Steps 2–5.**

### Task 4: The archive + retention (req. 14)

Čl. 6 st. 5 requires enabling comparison of *prethodno objavljene* against *realtime* prices, so prior snapshots must remain retrievable.

**Carried forward from the Task 1 review.** `DELETE` on `cenovnik_snapshots` is deliberately left open in v19 so this purge can reach an expired row — which means the retention purge is the **only** code permitted to delete from that table, and that needs its own assertion. Nothing in the engine distinguishes a purge from a cover-up.

- [ ] **Step 1: Write the failing tests** — snapshots list newest-first per outlet (ties on `generated_at` broken by the larger `id`); a snapshot body is byte-identical to what was published; retention resolves through the shared `retention_policies` table with a floor tied to the **čl. 213 two-year limitation**; the purge never removes the current snapshot for an outlet even if it is older than the floor; no other module deletes from `cenovnik_snapshots`.
- [ ] **Steps 2–5.**

### Task 7: Publish targets — local folder now, hosted later (reqs. 13, 15)

**Interfaces:** `trait PublishTarget { fn publish(&self, body: &str, outlet: &str, now: &str) -> Result<String, AppError>; }`, `LocalFolderTarget`, and a `NotConfigured` default.

The fetchability rules (req. 13) are written into the trait's doc comment as a **contract on any future implementation**: no login, no CAPTCHA, no JS requirement, no `robots.txt` disallow, no bot-fight rule, stable URL, correct `Content-Type`. Čl. 6 st. 5 is a duty to *enable*; putting the cenovnik behind bot protection would manufacture a breach for our own customer.
