# SW-10 + SW-13 + SW-17 — ZZPL Trio — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the tamper-evident audit log and the shop-side remote-support approval (SW-10), the three-class employee lifecycle with a time-driven purge (SW-13), the internal breach record with the Pravilnik 40/2019 export (SW-17), and the generated čl. 47 evidencija radnji obrade that SW-17 depends on.

**Architecture:** One migration (v18) carries all four stores. The audit log is append-only and hash-chained, with its exclusion list enforced at the write boundary rather than by convention. The employee record splits into three physically separate classes so that the purge job is *structurally* incapable of touching the two it must not. All retention decisions route through the shared `retention_policies` table SW-14 created.

**Tech Stack:** Rust (rusqlite, serde, sha2) + Tauri v2 commands; React 19 + TypeScript + shadcn/ui + vitest; bun.

### Task 1: Migration v18 — the four stores

### Task 2: `audit.rs` — hash chain + write-boundary exclusion filter

**Files:** Create `src-tauri/src/audit.rs`; modify `lib.rs`, `Cargo.toml` (add `sha2` if absent).

**Interfaces:** Produces `AuditAction` enum, `AuditDraft`, `chain_hash(prev: &str, draft: &AuditDraft) -> String`, `reject_forbidden_content(draft: &AuditDraft) -> Result<(), AppError>`, `verify_chain(rows: &[AuditRow]) -> ChainVerdict`.

The exclusion list is **enforced at the write boundary, not by convention** (req. 4). This is the load-bearing test of the whole module.

- [x] **Step 1: Write the failing tests**

**Deviations recorded during implementation** (all additive; nothing the plan asked for was dropped):

1. `chain_hash` also covers **`support_session_id`** — nine fields, not the eight the plan listed. A field outside the digest can be cut off a row in silence, and the support link is precisely the čl. 48 st. 2 evidence about who was inside the shop's data. Pinned by `the_support_session_link_is_covered_by_the_chain`.
2. `verify_chain` is **anchored on genesis** (`rows[0].prev_hash` must be `""`), not merely link-to-link, so a deleted FIRST row cannot verify as a shorter but intact chain. Pinned by `a_deleted_genesis_row_breaks_the_chain`.
3. The whitespace rule applies to **every textual field of the draft**, not only a `query` field — the draft has no `query` field, so the only way a search string can reach the table is disguised as `object_type` or `object_id`, which is where the boundary catches it.
4. Added a **`≥ 9`-digit-run** rule. Req. 4 names the *telephone number* alongside the JMBG and the PAN, and the v18 commit message explicitly deferred phone coverage to this boundary. Nothing this log legitimately references is nine digits long.
5. Added the **čl. 48 st. 2 primalac** rule (`otkrivanje` without a recipient class), mirroring the v18 CHECK, so the refusal reaches the operator as a sentence rather than as a raw SQLite constraint failure.
6. Distinct error codes: `audit_missing_reason` / `audit_missing_recipient` / `audit_forbidden_content`. Only the last is pinned by the plan's test.

**Review fixes** (second commit on Task 2; deviations 2 and 3 above are superseded where they conflict):

7. **Tail truncation is now detectable.** Deviation 2's genesis anchor catches a deleted FIRST row but not a deleted LAST row — the survivors are a shorter chain that reconciles perfectly, and deleting the newest rows is the tamperer's first move. Added `verify_chain_anchored(anchor_prev, anchor_id, rows, highest_ever_id) -> ChainVerdict` with a new `ChainVerdict::Truncated`. The anchor is `sqlite_sequence.seq`: `audit_events.id` is `INTEGER PRIMARY KEY AUTOINCREMENT`, so `seq` is the highest id ever ISSUED and a DELETE does not lower it. Pinned by `a_truncated_tail_is_caught_only_by_the_sequence_anchor`.
8. **`chain_hash` takes the row `id`** — ten fields, and the signature is `chain_hash(prev, id, draft)`, not the `chain_hash(prev, draft)` the plan listed. Without it, the answer to deviation 7 is to renumber a surviving row into the gap so the highest id still matches. **Contract for Task 4:** the id must be chosen before the hash is computed — `sqlite_sequence.seq + 1` read inside the same transaction and inserted explicitly, not left to AUTOINCREMENT. Pinned by `a_row_renumbered_into_the_gap_is_caught`.
9. **`verify_chain_from(anchor_prev, rows)`**, with `verify_chain(rows)` redefined as `verify_chain_from(GENESIS_PREV_HASH, rows)`. Req. 6 forbids „trajno“ on this log and v18 leaves DELETE open precisely so expiry can remove a row — and expiry removes the OLDEST rows, i.e. the head, where the genesis anchor sits. Without this the first legitimate purge reports a permanent break indistinguishable from tampering. **Contract for Task 5:** the purge persists the `hash` and the `id` of the last row it removed; that pair is the new anchor. Pinned by `a_head_purged_log_verifies_on_the_purge_anchor` and `an_emptied_log_is_intact_only_when_nothing_was_ever_written`.
10. **`object_type` is a closed `AuditObjectType` enum**, superseding deviation 3's shape scan of that field. A scan is the wrong tool for a code constant: „Marković“ carries no whitespace and no digits. Closing it also makes a search row *unrepresentable* — there is no `pretraga` variant. v18 pins no list for this column (its CHECK is a shape, not a vocabulary), so the enum is the contract and the codes are pinned by `every_code_round_trips_and_matches_the_v18_check_lists`.
11. **`object_id` is whitelisted, not blacklisted.** The old rule refused „Petar Petrović“ and accepted „Petrović“ — and a bare surname is exactly the search a shop runs, which req. 4 bars outright. The shape is now digits in optional hyphen-separated groups (`3`, `10422`, `2026-000117`), bounded at 32 characters, with the JMBG / Luhn / long-run rules kept as the inner guard. No letters: a symbolic reference belongs in the closed `AuditObjectType`, not in the id. New codes `nije_interna_oznaka` and `predugacka_oznaka`. Pinned by `a_name_or_an_e_mail_in_the_object_id_is_refused`, `an_overlong_object_id_is_refused` and the extended `a_search_query_string_is_refused`.
12. **The length prefix in the digest is pinned** by `the_length_prefix_keeps_the_preimage_unambiguous`. It was load-bearing prose guarded by nothing: a mutation dropping the prefix survived all 15 original tests.

### Task 3: Support approval — the `[LEGAL]` half of SW-10

**Files:** Create `src-tauri/src/commands/audit.rs`; modify `lib.rs`.

**Interfaces:** `support_request_access`, `support_grant_access(scope, duration_minutes)`, `support_end_session`, `support_active_session`.

Req. 2: the owner grants access with an explicit scope and duration. **That approval record is the čl. 46 nalog**, and it is worth more evidentially than the session log.

- [x] **Step 1: Write the failing tests** — a grant records who/when/scope/expiry; an expired grant is not active; ending a session stamps `ended_at`; a session cannot be granted by a cashier; every grant and end writes an `audit_events` row.
- [x] **Steps 2–5:** implement, run, commit.

**Deviations recorded during implementation** (all additive; nothing the plan asked for was dropped):

13. **`support_request_access` is the support side ENTERING under an existing nalog**, not a pending request awaiting approval. `support_sessions` has no pending state — `granted_by`, `granted_at`, `scope` and `expires_at` are all NOT NULL — so an ungranted request is unrepresentable, and v18's `CHECK (ended_at IS NULL OR started_at IS NOT NULL)` means something has to stamp `started_at` before `support_end_session` can stamp `ended_at`. This command is that something. It is gated by the **live nalog and nothing else**: čl. 46 makes the nalog the condition, and the obrađivač holds no account on this till. Pinned by `support_cannot_enter_without_a_live_nalog` and `entering_under_a_live_nalog_stamps_started_at_once`.
14. **The entry line is an `otkrivanje` to `obradjivac_tehnicke_podrske` with `actor_user_id` NULL.** The recipient vocabulary Task 2 built has that class for exactly this event, and čl. 48 st. 2's *identitet primaoca* is what it answers. The actor is NULL because borrowing the vlasnik's id would record an access the vlasnik did not make; the session link carries the nalog, its obim and who signed it. Pinned by `the_entry_line_is_a_disclosure_to_the_processor_with_no_borrowed_actor`.
15. **Ending a nalog nobody entered is a REVOCATION, not an end.** The v18 CHECK refuses `ended_at` without `started_at`, and „withdrawn before anyone used it“ is a materially different fact from „the support call finished“, so `support_end_session` stamps `revoked_at` + `revoked_by` in that case. Pinned by `ending_a_nalog_that_was_never_entered_revokes_it`.
16. **The duration is bounded** (1 … 1440 minutes) and the scope is bounded (1 … 500 characters, trimmed). Req. 2 asks for a *per-session* approval; a nalog measured in weeks is an open-ended one with a date printed on it. Pinned by `a_grant_needs_an_explicit_positive_and_bounded_duration` and `a_grant_needs_a_scope`.
17. **One live nalog at a time.** A second grant while one is still live is refused (`support_nalog_vec_izdat`): two live nalozi make „what is authorised right now“ unanswerable, which is the one question the record exists to answer. An expired, ended or revoked nalog blocks nothing. Pinned by `a_second_grant_while_one_is_live_is_refused`.
18. **`support_end_session` is admin-gated too**, not only the grant — the nalog is the rukovalac's instrument. Expiry covers the unattended case. Pinned by `a_cashier_cannot_end_the_vlasniks_nalog`.
19. **Task 3 owns the append primitive**, `append_audit_event(conn, draft)`, which Task 4's `record_audit` wraps: the plan requires grant and end to write `audit_events` rows, and those rows must chain. It honours Task 2's contract — `reject_forbidden_content` first, then the id chosen **before** the digest as `MAX(MAX(id), sqlite_sequence.seq) + 1` and inserted explicitly. It takes the caller's `Connection`, so the log line and the fact it describes commit or roll back together. Pinned by `every_grant_and_end_writes_a_chained_audit_row` and `the_audit_line_and_the_nalog_share_one_transaction`.
20. **Expiry is decided on parsed instants, never on string ordering.** RFC3339 renders the same moment with and without a fractional part and „09:00:00.5Z“ sorts *before* „09:00:00Z“ lexicographically, so the active-window test is `granted_at <= now < expires_at` in Rust. The expiry is exclusive. Pinned by `an_expired_grant_is_not_active`.

### Task 4: Audit write path + Poverenik export

**Files:** Modify `src-tauri/src/commands/audit.rs`.

**Interfaces:** `record_audit(state, draft, now)`, `audit_search(from, to, actor)`, `audit_export_csv`.

- [x] **Step 1: Write the failing tests** — a recorded row chains onto the previous; `record_audit` rejects forbidden content before writing; there is **no** update or delete command registered at all (assert by grepping `lib.rs` in a test, or by the absence of the function); the export renders offline and covers a date range and an actor.
- [x] **Steps 2–5:** implement, run, commit.

**Deviations recorded during implementation** (all additive; nothing the plan asked for was dropped):

21. **`record_audit` takes an `AuditEntry`, not an `AuditDraft`.** The plan's signature is `record_audit(state, draft, now)`, but a draft carries `at` and `actor_user_id`, which would make `now` redundant and — worse — would let a caller backdate a line or attribute an access to a colleague. `AuditEntry` is the draft minus exactly those two fields: the instant comes from `now`, the actor from the server-side session. Pinned by `record_audit_stamps_the_instant_and_the_actor_itself`.
22. **The actor is read with `session_user_id`, not `require_session`.** Req. 23's purge line is time-driven and has no human actor, so an actorless line must be writable; an absent actor is honest evidence, a borrowed one is not. Same test.
23. **`record_audit` is NOT a `#[tauri::command]`.** The plan lists it as a Rust interface and only the two read verbs are registered, so no webview caller can dictate a log line. Task 5's `personnel_get` records its own `uvid` server-side through this function; the frontend never asserts that an access happened.
24. **`audit_search` / `audit_export_csv` take an `AuditQuery` struct** (`from`, `to`, `actorUserId`) rather than three positional parameters — house style, mirroring `ReportDateQuery`. Both bounds are bare `gggg-MM-dd` days, both inclusive, and an RFC3339 instant is **refused** rather than truncated: a bound the caller believes is a moment and the query treats as a day discloses more, or less, than was asked for. Pinned by `a_malformed_date_range_is_refused`.
25. **The izvod records its own disclosure** — an `otkrivanje` on `audit_log` to the class `poverenik` with razlog `inspekcija`, written after the file exists (an export that failed disclosed nothing). The `object_id` is the id of the newest row inside the izvod, i.e. how far the disclosure reached. Task 2 built the `AuditObjectType::AuditLog` variant for exactly this. Pinned by `the_izvod_is_recorded_as_a_disclosure_to_the_poverenik`.
26. **Reading the log on screen is deliberately NOT logged.** A čl. 48 st. 2 line about an uvid into the log is itself an uvid into the log, and a refreshing panel would fill the shop's evidencija with nothing else. The disclosure that leaves the till is the fact worth recording, and it is.
27. **The reader reports the chain verdict, and the izvod carries it** (req. 7 puts tamper-evidence above completeness). `ChainStatus` walks the WHOLE surviving log — never the filtered slice, because a row removed outside the range is still a row removed — using `verify_chain_anchored` with `sqlite_sequence.seq` as `highest_ever_id`.
