# SW-10 + SW-13 + SW-17 — ZZPL Trio — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the tamper-evident audit log and the shop-side remote-support approval (SW-10), the three-class employee lifecycle with a time-driven purge (SW-13), the internal breach record with the Pravilnik 40/2019 export (SW-17), and the generated čl. 47 evidencija radnji obrade that SW-17 depends on.

**Architecture:** One migration (v18) carries all four stores. The audit log is append-only and hash-chained, with its exclusion list enforced at the write boundary rather than by convention. The employee record splits into three physically separate classes so that the purge job is *structurally* incapable of touching the two it must not. All retention decisions route through the shared `retention_policies` table SW-14 created.

**Tech Stack:** Rust (rusqlite, serde, sha2) + Tauri v2 commands; React 19 + TypeScript + shadcn/ui + vitest; bun.

### Task 1: Migration v18 — the four stores

**Files:** Modify `db/migrations.rs`, `db/mod.rs` (count, `CORE_TABLES`, `EXPLICIT_INDEXES`).

**Interfaces:** Produces `audit_events`, `support_sessions`, `personnel_records`, `data_breaches`, `processing_activities`.

Key schema decisions the tests must pin:

- `audit_events.action` is a **closed enum CHECK** mirroring čl. 48 st. 1: `unos | menjanje | uvid | otkrivanje | uporedjivanje | brisanje`.
- `audit_events` has **`prev_hash` and `hash`**, both NOT NULL, and **no `updated_at`** — nothing may ever update a row.
- `audit_events.actor_user_id` is a **FK to users**, never a name column. There is no free-text column on the table at all except `reason_code`, which is itself a closed enum.
- `personnel_records` references `users(id)` **without `ON DELETE CASCADE`** (req. 24) — a deleted account must not be able to take the personnel record with it.
- `data_breaches.saznanje_at` is NOT NULL (the 72 h anchor) and `occurred_at` / `discovered_at` are separate nullable columns.
- `processing_activities` mirrors čl. 47 st. 1's items with a retention column per category (t. 6).

- [ ] **Step 1: Write the failing tests**

```rust
    #[test]
    fn the_chain_detects_a_tampered_row() {
        let rows = vec![row("a", 1), row("b", 2), row("c", 3)];
        assert_eq!(verify_chain(&rows), ChainVerdict::Intact);

        let mut tampered = rows.clone();
        tampered[1].object_id = "999".to_string();
        assert!(matches!(verify_chain(&tampered), ChainVerdict::BrokenAt(1)));
    }

    #[test]
    fn a_deleted_row_breaks_the_chain_too() {
        let rows = vec![row("a", 1), row("b", 2), row("c", 3)];
        let mut gapped = rows.clone();
        gapped.remove(1);
        assert!(matches!(verify_chain(&gapped), ChainVerdict::BrokenAt(_)));
    }

    /// ZZPL čl. 48 st. 2 requires a *razlog* for access and disclosure.
    #[test]
    fn uvid_and_otkrivanje_require_a_reason_code() {
        for action in [AuditAction::Uvid, AuditAction::Otkrivanje] {
            let draft = draft_with(action, None);
            assert!(reject_forbidden_content(&draft).is_err(), "{action:?} needs a razlog");
        }
        for action in [AuditAction::Unos, AuditAction::Menjanje] {
            let draft = draft_with(action, None);
            assert!(reject_forbidden_content(&draft).is_ok());
        }
    }

    /// A log that accumulates personal data breaches čl. 5 st. 1 t. 3 and
    /// enlarges the very attack surface it exists to shrink.
    #[test]
    fn a_jmbg_shaped_value_is_refused_at_the_write_boundary() {
        let draft = draft_with_object_id("1234567890123"); // 13 digits
        let error = reject_forbidden_content(&draft)
            .expect_err("a JMBG-shaped id must not reach the log");
        assert!(matches!(error, AppError::Business { code: "audit_forbidden_content", .. }));
    }

    #[test]
    fn a_search_query_string_is_refused() {
        // A query for a customer's name IS personal data about that customer.
        let draft = draft_with_query("Petar Petrović");
        assert!(reject_forbidden_content(&draft).is_err());
    }

    #[test]
    fn a_card_pan_shaped_value_is_refused() {
        let draft = draft_with_object_id("4111111111111111");
        assert!(reject_forbidden_content(&draft).is_err());
    }
```
