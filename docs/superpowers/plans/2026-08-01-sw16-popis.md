# SW-16 — Popis — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the annual and nivelacija popis as a two-phase blind count with two statutory signature events, the required separate lists, a structured izveštaj, a computed deadline engine, and a write-lock on posting.

**Architecture:** A state machine (`draft → counting → counted_signed → computed → computed_signed → posted`) is the whole module. Phase B data is unreachable from Phase A **at the query layer**, not merely hidden in the UI — that is what makes PoP čl. 8 st. 5 a property of the system rather than a UI convention. Deadlines are computed from the FS filing rule, never tabulated.

**Tech Stack:** Rust (rusqlite, serde) + Tauri v2 commands; React 19 + TypeScript + shadcn/ui + vitest; bun.

## Global Constraints

- **Money is integer minor units; quantities milli-units.** Never floating point.
- **Timestamps RFC3339 passed as a `now: &str` param.** Never `datetime('now')` in decision code, and **never a wall clock in the deadline engine**.
- **Serbian Latin diacritics** in every operator string; Serbian quotes open `„` and close `“`.
- **Migrations APPEND-ONLY.** Read the current count from `db/mod.rs` first; this is the next free version.
- **NO fine figure outside `legal.rs`**; new notices go into **both** guard lists with the count bumped.
- **No book quantity may be readable during Phase A** — enforced in the query layer and asserted by test.
- **There is no obrazac for the popisna lista.** Do **not** carry over the SW-9c KEP print-fidelity constraints. **But the izveštaj content IS prescribed** (PoP čl. 13 st. 1).
- **Never boot the app.** Verify only via the gates.

### Task 1: Migration — the popis stores

`popis_sessions`: `id`, `vrsta` (`godisnji | nivelacioni`), `prodajno_mesto`, `datum_popisa`, `period_from`, `period_to`, `status` (the six-state enum), `plan_rada_json`, `odluka_ref`, `usklađivanje_potvrdjeno_at` (the čl. 20 st. 3 gate), `perpetual_odluka_ref`, `posted_at`, `created_at`, `updated_at`.

`popis_lines`: `id`, `session_id`, `lista_vrsta` (`roba | oštećena | van_objekta | gotovina | potraživanja | konsignacija`), `sifra`, `naziv`, `vrsta`, `jedinica_mere`, `stvarna_kolicina_milli`, `blizi_opis`, **`knjigovodstvena_kolicina_milli` (nullable, written only at the Phase A→B transition)**, `cena_minor`, `created_at`, `updated_at`.

`popis_signatures`: `id`, `session_id`, `faza` (`a | b`), `potpisnik`, `potpisano_at`, `snapshot_hash`, `created_at`. Immutable.

`popis_commission`: `id`, `session_id`, `ime`, `uloga`, `rukuje_imovinom` (0/1), `created_at`.

- [x] **Step 1: Write the failing tests** — the tables exist; the status enum is a closed CHECK; a `popis_signatures` row has no `updated_at`; `knjigovodstvena_kolicina_milli` is nullable; **a survival test applying `MIGRATIONS[..N]` to a raw Connection, seeding, `drop(conn)`, then `Db::new`** — mirror commit `270796c`.
- [x] **Steps 2–5.** Landed as migration **v20** (`popis_stores_blind_count_and_posting_lock`). Beyond the four tables, the migration enforces two module invariants in the engine rather than leaving them to a later layer, because migrations are append-only and these two cannot be added later without a second migration the plan does not budget for: **the čl. 8 st. 5 blind count is a write guard** (a book quantity is refused while the session is in `draft`/`counting` **and while no `faza = 'a'` signature exists for it**, so during a count none exists for any query, export or backup to leak — req. 29), and **posting write-locks the session, its lines, its commission and any new signature** (req. 41), with `popis_signatures` immutable from the moment each signature is taken. The guard is anchored on the potpis rather than on `status` alone because `status` is a claim any `UPDATE` can make — a session flipped or born into `counted_signed` with no signature behind it is refused the book data. **Contract for Task 4:** `popis_sign_phase_a` must write the signature row *before* it populates any `knjigovodstvena_kolicina_milli` (the statutory order anyway), and `popis_post` must write everything else *before* flipping to `posted`, since that flip is the last permitted write. No popis table may be written with `INSERT OR REPLACE`/upsert: `REPLACE` deletes and re-inserts, so no `BEFORE UPDATE` lock fires. `DELETE` stays open on all four tables for the req. 42 retention purge, as v18 and v19 each reasoned. Deviations: identifiers and stored enum values are ASCII-folded per the schema-wide convention (`uskladjivanje_potvrdjeno_at`, `ostecena`, `potrazivanja`), and `popis_commission.uloga` is a closed enum (`predsednik | clan | jedno_lice`) rather than free text, so the čl. 6 st. 1 single-person popis is expressible instead of implied.

### Task 2: `popis.rs` — the state machine + the blind-count property

**Interfaces:** `PopisStatus` enum, `advance(current, event) -> Result<PopisStatus, AppError>`, `book_quantities_visible(status) -> bool`.

- [ ] **Step 1: Write the failing tests**

```rust
    /// PoP čl. 8 st. 5: book quantities must not reach the commission before the
    /// counted state is written and signed. A UI that merely hides them is not
    /// enough — the property belongs to the state machine.
    #[test]
    fn book_quantities_are_invisible_until_phase_a_is_signed() {
        for status in [PopisStatus::Draft, PopisStatus::Counting] {
            assert!(!book_quantities_visible(status), "{status:?} must be blind");
        }
        for status in [PopisStatus::CountedSigned, PopisStatus::Computed, PopisStatus::ComputedSigned, PopisStatus::Posted] {
            assert!(book_quantities_visible(status), "{status:?} may reveal");
        }
    }

    #[test]
    fn phase_b_cannot_be_entered_without_the_phase_a_signature() {
        let error = advance(PopisStatus::Counting, PopisEvent::Compute)
            .expect_err("computing before the čl. 8 st. 5 signature must be refused");
        assert!(matches!(error, AppError::Business { code: "popis_not_signed", .. }));
    }

    #[test]
    fn a_posted_popis_admits_no_further_transition() {
        for event in [PopisEvent::Count, PopisEvent::Compute, PopisEvent::SignA, PopisEvent::SignB, PopisEvent::Post] {
            assert!(advance(PopisStatus::Posted, event).is_err(), "{event:?} after posting");
        }
    }
```
